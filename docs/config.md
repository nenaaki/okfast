# okfast.toml の書き方

okfast の設定ファイルの説明です。`okfast config reference` で、使っている okfast に合った版を表示できます。

## 前提

- OKF 0.2 には同義語の決まりがありません。frontmatter で必須なのは `type` だけで、type の値もほかのキーも自由です（仕様 §4.1）。そのため okfast は、同義語がどこにあるかを知りません。**同義語をどこからどう取り出すかは、バンドルごとにこのファイルで宣言します。**
- 置き場所はバンドルの root の `okfast.toml` です（`--config <path>` でも渡せます）。ファイルがなければ言い換えはしません。
- `okfast search`（読む範囲を返す検索）の設定（`[search.sections]`・`[search.recent]`・`[search.must_read]`）もこのファイルに書きます。行の日付をどこから取るかも、同じ理由でバンドルごとに宣言します
- 未知のキーや綴りの誤りはエラーになり、行と列が示されます。

## 手順（AI 向け）

1. `okfast -b <root> config init > okfast.toml` で下書きを作る。根拠はコメントに書かれる。見つからなかったものはコメントアウトされている
2. 下書きを読み、バンドルの実際の書き方（表の列名・区切り・どのページを検索から除くか）に合わせて直す
3. `okfast -b <root> config check` を実行し、**設定の警告（`!` の行）がなくなるまで** 2 に戻る。終了コードは、設定の警告なしが 0、ありが 1、設定ファイルのエラーが 2
   - `?` の行は辞書の中身についての所見（同じ語が複数の行にある、長すぎる呼び名、リンク切れ）。意図どおりのこともあるので、設定では直さず利用者に伝える。終了コードには影響しない
4. `okfast -b <root> aliases <語>` で、代表的な語が意図どおりに言い換えられるかを確かめる
5. `okfast search` を使うなら、init が根拠つきで提案した `[search] topic_keys` と `[search.recent] date_sources` を確かめ（check がキーを持つページの数、日付の取れた行の数と例を出す）、必ず読む節の見出しの語・決まったページは利用者に確かめてから書く

## 言い換えの約束

- 問いの語が、ある概念の概念名か呼び名に一致したら、その概念の呼び名をすべて足して検索する
- **連鎖しない。** A＝B と B＝C が別の概念にあっても、A から C へは広げない
- 照合は NFKC 正規化・大文字小文字・空白の違いを無視する。ただし `short_max` 文字以下の英数字の語は、大文字小文字を区別し、前後が英数字でないときだけ当てる
- 言い換えには必ず出所（ページと行）が出る

## ページの選び方（`pages` と `when`）

```toml
pages = { path = "glossary/*.md" }                  # path は glob。* は / をまたがない、** はまたぐ
pages = { path = ["a.md", "b/**"] }                 # 複数の glob は、どれかに当たればよい
pages = { type = "Term" }                           # path 以外のキーは frontmatter のキー
pages = { type = "Term", category = ["用語", "別名"] }  # キーどうしは AND、値の並びは OR
```

パスはバンドルの root からの相対パスで、区切りは `/` です。`index.md` と `log.md`（OKF の予約名）と、`.` で始まる名前のファイル・ディレクトリは、バンドルに含まれません。

## `[[aliases.table]]` — 表から取り出す

表の 1 行を 1 つの概念とし、呼び名の列にある語どうしを同義語にします。何個でも書けます。

| キー | 必須 | 既定値 | 意味 |
|---|---|---|---|
| `pages` | ○ | | 表を探すページ |
| `names` | ○ | | 呼び名の列の見出し（完全一致）。同じものだと言える語だけを書く列。`["用語", "別表記"]` のように複数の列を並べると、どの列の語も呼び名になる |
| `concept` | | なし | 概念名の列の見出し。概念名でも引けるようになるが、言い換えには足さない。指定すると、この列がない表は使わない |
| `split` | | `["、", ","]` | セルの中の区切り |
| `strip_notes` | | `[]` | 呼び名から外す注記の開き括弧（例: `["（", "("]`）。対応する閉じ括弧までを外す。「Widget Pro（旧称）」→「Widget Pro」 |
| `boost` | | なし | この列（複数可）のリンクの行き先を、検索結果の上位に出す |

ページの中の表のうち、`names` の列（と `concept` を指定したならその列）をすべて持つ表だけを使います。ほかの表は無視されます。

セルの扱い:
- リンク `[表示](行き先)` は表示の文字を語にする。脚注 `[^id]` は除く
- ダッシュだけのセル・語（`—` `–` `-` など）は「該当なし」として語にしない
- リンクの行き先は、`/` で始まればバンドルの root から、そうでなければリンクのあるページのディレクトリから解決する（OKF 0.2 §6.1）

### `concept` と `names` の使い分け

- 概念名が呼び名の列にも書かれている表（`| 概念 | 呼び名 |` で、呼び名に概念名も並べている）→ `concept = "概念"`、`names = "呼び名"`
- 概念名が呼び名の列に書かれていない表（`| 用語 | 別表記 |` で、別表記には別の書き方だけがある）→ `names = ["用語", "別表記"]`。`concept` にすると、別表記で引いたときに用語へ戻らない
- `okfast config init` は表の中身を見て、どちらかを提案する

### `[[aliases.table.conditional]]` — 条件付きの列

特定のページを検索するときだけ使う列です（例: 文字起こしの誤認識は、文字起こしのページを検索するときだけ使う）。直前の `[[aliases.table]]` に付きます。

| キー | 必須 | 意味 |
|---|---|---|
| `column` | ○ | 列の見出し |
| `when` | ○ | 検索するページがこれに当たるときだけ、この列の語を使う（書き方は `pages` と同じ） |

## `[[aliases.frontmatter]]` — frontmatter から取り出す

ページの `title` と、指定したキーの値を同義語にします。そのページが主題のページになります。

| キー | 必須 | 既定値 | 意味 |
|---|---|---|---|
| `keys` | ○ | | 別名のキー（値は文字列か文字列の配列） |
| `pages` | | すべてのページ | 対象のページ |
| `include_title` | | `true` | `title`（なければファイル名）も呼び名に含める |

## `[aliases.match]`

| キー | 既定値 | 意味 |
|---|---|---|
| `short_max` | `3` | この文字数以下の ASCII 英数字（と `.` `-`）の語は、大文字小文字を区別し、単語として当てる |

## `[aliases.trust]` — 取り出し元を絞る

取り出し元のページを frontmatter の値で絞ります。**キーを持たないページは使いません。**

| キー | 必須 | 意味 |
|---|---|---|
| `key` | ○ | frontmatter のキー（例: `credibility`） |
| `allow` | ○ | 使う値の並び（例: `["A", "B"]`） |

## `[search]`

| キー | 既定値 | 意味 |
|---|---|---|
| `exclude` | `[]` | 既定で検索しないページの glob。`okfast grep --all` で含める。辞書のページそのもの（どの語でも当たる）を入れておくとよい |
| `show_keys` | `[]` | `okfast search` の範囲の見出しに値を出す frontmatter のキー（例: `["credibility"]`）。JSON では `meta` に入る |
| `topic_keys` | `["title"]` | `okfast search` で主題のページを決める frontmatter のキー（例: `["title", "description", "tags"]`）。値に語が当たったページ（と辞書の `boost` のリンク先）の範囲は点が上がる（下の「順位の付け方」）。`title` がないページはファイル名を使う。OKF 0.2 では説明のキーが決まっていないので、既定は `title` だけ |

以下の 3 つは `okfast search`（読む範囲を返す検索）だけが使います。

**順位の付け方**: 行の点は BM25（行を 1 つの文書とし、語ごとの idf・行の中の出現回数・行の長さで決める。`[search.sections]` の `tf`・`k1`・`b`）。主題のページでは、ページの `topic_keys` の値か辞書の `boost` に当たった語の idf の割合（`share`、0〜1）を取り、行の点に `1 + share` を掛けます。全部の語に当たるページほど強く上がり、1 語だけ当たるページは少しだけ上がります。範囲の点は `[search.sections] score` で決め、点の高い順（同点なら日付の新しい順）に並べます。脚注の定義の行（`skip_footnotes`）と、リンクの行き先（`](...)` の中）は当たりに数えません（grep は数えます）。

### `[search.sections]` — 節の切り方

節は、見出し（`#`〜`######`）の行から次の見出し（レベルを問わない）の手前までです。最初の見出しより前の本文は、見出しなしの節になります。

| キー | 既定値 | 意味 |
|---|---|---|
| `max_lines` | `40` | これより長い節は、当たった行の前後だけを範囲にする（重なる・隣り合うものはつなぐ） |
| `window` | `4` | 長い節で、当たった行の前後に含める行の数 |
| `min_chars` | `0` | 本文（前後の空白を除く）がこの文字数より短い行は、当たりに数えない。見出しの行は短くても数える |
| `score` | `"decay"` | 範囲の点の決め方。`decay` は当たった行の点を高い順に並べ、1・1/2・1/4… を掛けて足す（同じ語の繰り返しの効きを抑えつつ、何行も当たる節を少し上げる）。`max` は語ごとに範囲の中で最も高い行の点を取って足す（繰り返しを数えない） |
| `skip_footnotes` | `true` | 脚注の定義の行（`[^id]: 出典の題名・パス`）を当たりに数えない（出典の題名に語が入りやすく、「出典」「関連」の節が上がるため）。日付の取り出し元（`footnote_source`）としては使う |
| `tf` | `"count"` | 行の点の tf（語の数え方）。`count` は行の中の出現回数（`A\|B` の言い換えはそれぞれ数えて足す。リンクの行き先は数えない）。表の 1 行に名前や語が何度も並ぶ行（その話題を正面から扱う行）が上がる。`binary` は当たったかどうかだけ（1 行 1 回） |
| `k1` | `1.2` | BM25 の k1。回数の効きの頭打ち（大きいほど回数が効く。0 なら回数を数えないのと同じ）。0 以上 |
| `b` | `0.5` | BM25 の b。行の長さの補正（0 なら長さによらない、1 なら長さに比例して軽くする）。0 から 1 まで |

### `[search.recent]` — 新しい記録と、行の日付の取り方

関連度の上位のあとに、日付の新しい範囲を足します。新しい記録が、語の少なさで上位から落ちないようにするためです。`--since`・`--sort date` もこの日付を使います。

| キー | 既定値 | 意味 |
|---|---|---|
| `count` | `4` | 足す範囲の数（`okfast search --recent N` で変えられる） |
| `pool` | `60` | 新しい記録を選ぶ候補。関連度の上位に入らなかった範囲のうち、順位の上から `pool` 個の中で日付の新しいものを選ぶ。関連度のごく低い範囲（開催前の予定の会議、先の予定の日付を書いた行、ほかのページの「関連」の節）が選ばれないようにするため。0 なら候補すべて |
| `date_sources` | `[]` | 行の日付の取り出し元。先に書いたものから探し、最初に見つかった日付をその行の日付にする。**空なら日付を使わない**（新しい記録は足さず、`--since`・`--sort date` はエラー） |
| `table_columns` | `[]` | `table_row` で、1 列目より先に見る列の見出し（完全一致） |

`date_sources` に書けるもの:

| 値 | 日付 |
|---|---|
| `table_row` | 表のデータ行の 1 列目（と `table_columns` の列）のセル。**セルが日付で始まるときだけ**、その日付を使う（「2026-03-02」「2026/3/2（月）」「11/20 定例」）。文の途中の日付（「第 6 回は 2027/6/14」など、先の予定のことが多い）は使わない。年のない日付（`M-D`・`M/D`）は、ページを書いた日（OKF 0.2 §5.2 の `generated.at`）の年で読む |
| `frontmatter:<キー>` | ページの frontmatter のキーの値（ページのすべての行に効く。例: `frontmatter:date`） |
| `footnote_source` | 行が参照する脚注 `[^id]` の定義の本文（出典のパス・題名）。リンク先のページは開かない |
| `heading` | 行が属する見出しと、その親の見出しのうち、いちばん近い日付つきのもの |

- 日付の書式は `YYYY-MM-DD` と `YYYY/MM/DD`（月・日は 1 桁も可）だけ。前後が数字のもの、ありえない月日は日付にしない。`table_row` 以外（frontmatter・脚注・見出し）では、1 つの文字列に複数あれば最も新しいもの
- 年のない日付は `table_row` のセルだけで読む（セルが `M-D` か `M/D` で始まるとき。すぐ後ろが数字・`-`・`/`・`.`・`:` なら日付にしない）。年は `generated.at` の年。ただし月が `generated.at` の月より 6 か月を超えて先なら前の年とみなす（1 月に書いたページの「12-20」は前年の 12 月 20 日）。`generated.at` がないページでは読まない（推測の日付は付けない）。年末年始をまたぐ表は年を書く
- 範囲の日付は、範囲の行の日付のうち最も新しいもの。日付の分からない範囲は、新しい記録と `--since` の候補にしない

### `[search.must_read]` — 必ず読む範囲

関連度によらず、結果の先頭に出す範囲です。未決・矛盾などの節は問いの語が少なく、関連度の上位に入りにくいためです。

| キー | 既定値 | 意味 |
|---|---|---|
| `topics` | `2` | 見出しを探す主題のページの数。主題のページ（`topic_keys` の値か辞書の `boost` に語が当たったページ）を `share` の高い順（同じなら当たった行の多い順）に選ぶ |
| `headings` | `[]` | 見出しにこの語のどれかを含む節を出す（正規化して部分一致） |
| `max_lines` | `60` | 出す節の行数の上限（超えたら先頭から） |
| `pages` | `[]` | `{ path = "<glob>", top = 3 }` の並び。当たったページのうち path に当たるものから、点の高い範囲を `top` 件出す。`exclude` に当たるページでもよい（決定の一覧などを既定の検索から除いたまま使える）。`window` を足すと、節の長さによらず当たった行の前後 `window` 行で切り出す。`window = 0` なら当たった行だけを 1 件ずつ出す（1 行 1 件の決定の一覧など。隣り合う行もつながない）。省くと `[search.sections]` の切り方 |

## 例

表と frontmatter の両方を使うバンドル:

```toml
[[aliases.table]]
pages   = { path = "glossary/別名表.md" }
concept = "概念"
names   = "呼び名"
split   = ["、"]
boost   = "主題のページ"

[[aliases.table.conditional]]
column = "文字起こしの誤認識"
when   = { path = "references/transcripts/**" }

[[aliases.frontmatter]]
keys = ["aliases"]

[aliases.trust]
key   = "credibility"
allow = ["A", "B"]

[search]
exclude    = ["glossary/別名表.md", "references/transcripts/**", "decisions/**"]
show_keys  = ["credibility"]
topic_keys = ["title", "description", "tags"]

[search.recent]
date_sources  = ["table_row", "frontmatter:date", "footnote_source", "heading"]
table_columns = ["日付"]

[search.must_read]
headings = ["未決", "矛盾", "未確認"]
pages    = [{ path = "decisions/*.md", top = 3, window = 0 }]
```

この設定が読む表（`glossary/別名表.md`）:

```markdown
| 概念 | 呼び名 | 文字起こしの誤認識 | 主題のページ |
|---|---|---|---|
| Widget Pro | Widget Pro、WP、ウィジェットプロ | ウジェットプロ | [Widget](/notes/widget.md) |
```

ページごとに別名を書く形式（frontmatter）:

```yaml
---
type: Product
title: Widget Pro
aliases: [WP, ウィジェットプロ]
---
```

## よくある誤り

| 症状（check の表示） | 原因と直し方 |
|---|---|
| 当たるページがない | `pages` の path・キーの値が違う。check が示す「列を持つ表があるページ」を見る |
| 列「…」を持つ表がない | 列名が見出しと完全一致していない。check が示す見出しをそのまま写す |
| 呼び名の列が空の行 | 概念名だけの行は言い換えない。呼び名の列に、概念名を含む呼び名を書く |
| 複数の概念にある語（?） | 同じ語が別々の行にある。同じものを別の表にも書いているだけなら問題ない。別のものなら、利用者に確かめて辞書を直す |
| 文字を超える呼び名（?） | 呼び名の列に説明文や注記が入っている。括弧の注記なら `strip_notes` で外す。説明文なら辞書を直す |
| 別表記で引いても用語に戻らない | `concept` に用語の列を書いている。`names = ["用語", "別表記"]` にする |
| 短い語 | 略語はほかの意味でも当たりやすい（例: 単位の MB）。誤って当たるなら呼び名から外す |
| when に当たるページがない | 条件付きの列が一度も使われない。`when` の path を直す |
| trust で除いたページ | 辞書のページに trust のキーがない。キーを書くか、trust を外す |
| 日付の取れた行がない（[search.recent]） | `date_sources` の取り出し元に、日付が書かれていない。check が示す内訳と、`config init` の提案を見る |
| must_read の path に当たるページがない | `[search.must_read] pages` の glob が違う。`index.md`・`log.md` は OKF の予約名でページにならない |
| generated.at がないので年が分からず読めない | 表の 1 列目に年のない日付（`M-D`）があるページに `generated.at` がない。frontmatter に `generated: { by: ..., at: ... }` を書くか、表に年を書く |
| キー … を持つページがない（topic_keys） | `[search] topic_keys` のキーを持つページがない。キーの名前を確かめる |
