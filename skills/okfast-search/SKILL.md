# okfast でナレッジを検索する

OKF バンドルの中を探すときは、Grep ツールや `rg`・`grep` ではなく `okfast grep` を使う。

- 同義語の辞書（バンドルの `okfast.toml` で宣言）で、語を自動で言い換える。略称・旧称・別表記で書かれたページも見つかる
- 全角半角・大文字小文字・空白の違いを無視して当てる
- 常駐プロセスが全ページをメモリに持っているので、ripgrep より速い（初回だけ少し遅い）

okfast の MCP ツール（`mcp__okfast__grep`・`mcp__okfast__search`・`mcp__okfast__aliases`）が使えるなら、シェルの `okfast` コマンドより先にそちらを使う（シェルを通さないぶん速い）。引数は下のオプションと同じ名前（`terms` に語の配列、`pages`・`context`・`max_per_page`、search は `top`・`per_page`・`since`・`sort`・`path` など）で、出力も同じ。

## 使い方

```sh
okfast -b <root> grep 語1 語2 ...        # どれかの語を含む行を、順位の高いページから出す
okfast -b <root> grep "A|B"              # | は自分で並べる言い換え（同じ語として扱う）
okfast -b <root> grep -C 2 語            # 当たった行の前後 2 行も出す（表の見出し・段落の文脈を見たいとき）
okfast -b <root> grep -m 10 語           # 1 ページに出す行を増やす（既定 5）
okfast -b <root> grep --full 語          # 上限なしですべて出す（出力が大きくなるので使わない。下の注意）
okfast -b <root> grep --pages 語         # 当たったページをすべて、1 ページ 1 行（題名・行数・抜粋）で
okfast -b <root> grep -l 語              # 当たったページのパスだけ（順位順・上限なし）
okfast -b <root> grep -c 語              # ページごとの行数だけ（順位順・上限なし）
okfast -b <root> grep --all 語           # 既定で除いているページ（辞書のページなど）も含める
okfast -b <root> aliases 語              # 何に言い換えられるかだけを見る（出所のページと行つき）
```

`--json`（1 行の JSON）はプログラム・試験用。読むのには使わない。

- `<root>` はバンドルの root（`okfast.toml` や層のディレクトリがあるところ）。今いるディレクトリが root なら `-b` は省ける
- 出力のパスは root からの相対パス。中身を読むときは `<root>/<パス>` を Read する
- 終了コード: 当たりあり 0、当たりなし 1、エラー 2

## 出力の読み方

```text
# grep: Widget Pro ／ 価格                       ← 問いの語
# 言い換え: Widget Pro → WP、ウィジェットプロ  (glossary/別名表.md:12)   ← 辞書による言い換えと出所
# 当たり: 120 行 / 40 ページ（検索 900 ページ）
# 表示: 上位 30 ページ・各 5 行まで（省いた行 35、行を出さないページ 10）…
# ページ: notes/widget.md「Widget Pro」 12 行・語 2/2・題名に当たり   ← ページごとの見出し
notes/widget.md:40:WP の価格は…                  ← パス:行番号:内容
# （このページのほかの 7 行: 52, 60, 71, …）      ← 出さなかった行の行番号
# ほかに当たったページ（順位順・行数）: a.md (3), b.md (2), …
```

- ページの順位は、主題のページ（辞書が指すページ）→ 当たった語の種類が多い → 題名に当たった → 見出しに当たった → 当たった行が多い、の順。**上から読めばよい**
- `語 2/2` は、問いの語のうちいくつがそのページにあるか。「A かつ B」のページは `語 2/2` のページ
- 出さなかった行は行番号で示される。続きは Read で、その行番号のあたりを読む（もう一度 grep しなくてよい）
- 長すぎる行（既定 300 文字超）は `…（N 文字のうち 300 文字まで）` で切られる。全文は Read で読む
- 出力の全体は約 1 万文字まで（`--max-chars`）。超える分のページは `# ほかに当たったページ` の一覧に回る
- 1 回の呼び出しで、grep を 1 つだけ実行する（`;` でつなぐと出力が合わさって長くなる）

## 読む範囲を決める（search）

問いに答えるために **どこを読むか** を決めたいときは、`grep` より `okfast search` を使う。結果は見出しで区切った節で、`パス:開始行-終了行` の範囲をそのまま Read すればよい。答えの行に語がなくても、同じ節に当たりがあれば範囲に入る。

```sh
okfast -b <root> search 語1 語2 ...        # 関連度の上位 8 範囲（1 ページ 2 範囲まで）
okfast -b <root> search -n 4 語            # 上位を減らす（--per-page で 1 ページの範囲の数）
okfast -b <root> search --since 2026-01-01 語   # その日以降の日付の範囲だけ
okfast -b <root> search --sort date 語     # 日付の新しい順（「最新の」「いちばん新しい決定は」など）
okfast -b <root> search --path "meetings/**" 語   # その層（ディレクトリ）だけ。既定で除くページも、ここで挙げれば含める
```

```text
# 主題のページ（点を上げる）: notes/widget.md   ← 題名などに語が入るページ。範囲の点が上がっている
## 必ず読む範囲（見出しや決まったページで選んだもの。関連度によらない）
notes/widget.md:18-21［§概要 > 未決｜credibility: A］   ← 未決・矛盾など、設定で決めた見出しの節
## 関連度の上位
notes/widget.md:10-16［2026-03-02｜§概要 > 価格｜credibility: A］   ← パス:開始行-終了行［日付｜§親 > 見出し｜frontmatter の値］
  10: ## 価格                                   ← 点の高い当たった行 2 行
  11: 価格は次のとおり。
## 新しい記録（関連度の上位に入らなかったもの）
```

- 範囲は Read の `offset` = 開始行、`limit` = 終了行 - 開始行 + 1 で読む。上から読み、答えが出たら止めてよい
- **「必ず読む範囲」は読み飛ばさない。** 未決・矛盾・決定の一覧など、答えを覆しうる節が入っている
- 「新しい記録」は、関連度では下でも日付が新しい範囲。古い記録と食い違えば、新しい方を答えにし、食い違いがあることも伝える
- `節 a-b の一部` は、長い節から当たった行の前後だけを切り出したもの。足りなければ節全体（a-b）を読む
- 順位は点の高い順。何行にもわたって語が当たる節、全部の語が題名などに入るページの節ほど上に来る。脚注の出典の行やリンクの行き先だけに語があっても当たりにならない
- 特定の層だけを読みたい（「会議の記録では」「文字起こしで確かめて」など）ときは `--path` で絞る
- `--since`・`--sort date` は、バンドルの設定に日付の取り方（`[search.recent] date_sources`）がないとエラーになる。そのときは使わない
- ページを網羅したいとき・語がどこに出るかを全部見たいときは grep（`--pages` など）を使う

## 出力を大きくしない

Claude Code は長いコマンドの出力をファイルに逃がし、そのファイルを読み直すのに手間がかかる。`-m`・`--max-pages`・`--max-chars` を大きくしたり、`--full` を付けたりしない。

- 出さなかった行の続きは、行番号を見て Read で読む
- 当たりが多すぎるときは、語を足して（`語 2/2` のページを見る）・語を具体的にして絞る
- **当たったページをすべて挙げる・網羅する** ときは `--pages` を使う。当たったページを全部、1 ページ 1 行（題名・行数・いちばん上の当たり行の抜粋）で出す。それで足りないページだけ Read する。Grep でページを 1 つずつ探し直さない
- 1 つのページの中だけを探すなら、Grep に `path` でそのページを渡してよい

## 探し方

1. まず利用者の言葉のまま `okfast grep` する。関係する語は 1 回の呼び出しにまとめて並べる（語ごとに呼び分けない）。言い換えは okfast がするので、自分で同義語を `|` で並べなくてよい（辞書にない言い換えを思いついたときだけ `|` で足す）
2. 上位のページの行と見出しを見て、読むページを決めて Read する。多くの場合、上位 1〜3 ページで足りる
   - 問いに答えるのが目的なら、grep の代わりに `okfast search` で読む範囲を直接もらってもよい（上の「読む範囲を決める」）
3. 当たりなしなら `# 言い換え` の行を見る。言い換えが出ていなければ辞書にない語なので、表記を変えるか、語を短くして探し直す。それでもなければ `--all` を試す
4. 「A かつ B」を含むページは、A と B を並べて grep し、`語 2/2` のページを見る

## okfast を使わない場面

- バンドルの外のファイル、`.md` 以外のファイル、`index.md`・`log.md`（OKF の予約名で、okfast は検索しない）
- 正規表現が必要なとき（okfast は語をそのまま探す）
- `okfast` コマンドがない・エラー（終了コード 2）になるとき。エラーの内容を利用者に伝えてから、Grep で探す

## 注意

- 辞書にない言い換えは okfast にも分からない。言い換えが足りない・おかしいと気づいたら、利用者に伝える（辞書や `okfast.toml` を直すのは okfast-config スキルの仕事）
- 書いた直後のページも、次の検索から反映される（常駐プロセスがファイルの変更を監視している）
