# okfast.toml を作る・直す

okfast は OKF バンドルを、同義語で言い換えながら検索する。同義語がどこにあるか（表のページと列、frontmatter のキー）は、バンドルの root の `okfast.toml` で宣言する。書式の説明は okfast 本体が持っているので、ここには手順だけを書く。

## 手順

1. 書式を読む: `okfast config reference`
2. 設定がなければ下書きを作る: `okfast -b <root> config init > <root>/okfast.toml`
   - 根拠（見つけた表・キー）がコメントに書かれる。見つからなかったものはコメントアウトされている
   - 既存の okfast.toml を上書きしないこと。あるなら init の出力は見比べるだけにする
3. 確かめる: `okfast -b <root> config check`
   - `!` の行が設定の警告。メッセージにある手がかり（似た見出し、列を持つ表があるページ、実際の見出し、文字列の配列のキー）に従って直す
   - **終了コードが 0（設定の警告なし）になるまで** 直しては check を繰り返す。2 は設定ファイルの文法の誤り（行と列が示される）
   - `?` の行は辞書の中身についての所見（同じ語が複数の行にある、長すぎる呼び名、リンク切れ）。設定では直さず、一覧にして利用者に伝える。辞書のページを直すかは利用者が決める。括弧の注記で長くなっているだけなら `strip_notes` で外してよい
4. 代表的な語で言い換えを確かめる: `okfast -b <root> aliases <語>`（出所のページと行が出る）
5. `okfast search`（読む範囲を返す検索）を使うなら、`[search.recent]`・`[search.must_read]`・`[search.timeline]`・`[search] show_keys`・`[search] topic_keys` も書く
   - 主題のページを決めるキー（`topic_keys`）は、init が根拠（そのキーを持つページの数）つきで提案したものを使う。既定は `title` だけ
   - 行の日付の取り方（`date_sources`）は、init が「根拠」つきで提案したものだけを使う。日付の書かれていない取り出し元を足さない。frontmatter のキーはページの全行に効くので、更新日のように記録の日付でないキーなら外す
   - 必ず読む節の見出しの語（`must_read.headings`）や決まったページ（`must_read.pages`）は、バンドルの書き方を推測せず、利用者に確かめてから書く。決まったページが 1 行 1 件の表なら `window = 0`（当たった行だけ）にする
   - 表の日付（`table_row`）は、セルが日付で始まるときだけ使われる。文の中に日付を書いた列は日付の列にしない
   - 表の 1 列目の日付に年がない（`MM-DD`）ときは、ページの `generated.at` の年で読む。check が「generated.at がないので年が分からず読めない」と出したら、利用者に伝える
   - check の `[search.recent]` の節で日付の取れた行の数と例を見て、意図どおりかを確かめる
   - 時系列の一覧（`[search.timeline]`）の行の種類（`kinds`）と変更の印（`superseded`）は、バンドルで決定・結論・変更をどう書いているか（`【決定】` などの印）を利用者に確かめてから書く。推測で書かない。check がパターンに当たる行の数と例を出す
   - 順位の調整（`[search.sections]` の `tf`・`k1`・`b`、`[search.recent] pool`）は既定のままにする。変えるのは、正解を用意した評価で効き目を確かめたときだけ
   - 代表的な語で `okfast -b <root> search <語>` を実行し、範囲の［日付｜§見出し］が意図どおりかを見る

## 守ること

- 同義語にするのは「同じものだと言える語」だけ。関連語や上位語を呼び名に入れない（言い換えは連鎖しないが、入れた語はそのまま検索に使われる）
- 推測で列名やパスを書かない。check の出力にある実際の見出し・パスを写す
- 短い略語（既定は 3 文字以下）は、ほかの意味でも当たりやすい。check の「短い語」を見て、誤って当たるものがあれば利用者に伝える
